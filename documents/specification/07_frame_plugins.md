## 1. Introduction

**Frame Plugins** are **compiler plugins written in Clean Language**. They extend the compiler by transforming DSL blocks into standard Clean code at compile-time.

### Design Goals

- **Simple to author**: Write plugins in Clean Language
- **Safe to run**: WASM sandbox at compile-time
- **Easy to distribute**: Single `.wasm` file + manifest
- **Self-hosting**: Clean Language extending itself

## 2. Plugin Architecture

### How Plugins Work

```
┌─────────────────────────────────────────────────────────────────┐
│                        SOURCE CODE                               │
│                                                                  │
│   plugins:                                                       │
│       my-plugin                                                  │
│                                                                  │
│   myblock: attr="value"                                         │
│       some content                                               │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                        COMPILER                                  │
│                                                                  │
│   1. Parse plugins: block in main.cln                            │
│   2. Load plugins from ~/.cleen/plugins/                        │
│   3. Find framework blocks (myblock:)                           │
│   4. Call plugin.expand_block("myblock", attrs, body)           │
│   5. Replace block with returned Clean code                     │
│   6. Continue compilation                                       │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                     EXPANDED CODE                                │
│                                                                  │
│   // Generated by my-plugin                                     │
│   some_generated_function()                                     │
│       // ... expanded implementation                            │
└─────────────────────────────────────────────────────────────────┘
```

### Plugin Directory Structure

Plugins are installed to `~/.cleen/plugins/<name>/<version>/`:

```
~/.cleen/plugins/
├── frame.server/
│   └── 1.0.0/
│       ├── plugin.toml       # Plugin manifest
│       └── plugin.wasm       # Compiled plugin
├── frame.data/
│   └── 1.0.0/
│       ├── plugin.toml
│       └── plugin.wasm
├── frame.auth/
│   └── 1.0.0/
│       ├── plugin.toml
│       └── plugin.wasm
├── frame.ui/
│   └── 1.0.0/
│       ├── plugin.toml
│       └── plugin.wasm
├── frame.canvas/
│   └── 1.0.0/
│       ├── plugin.toml
│       └── plugin.wasm
└── my-custom-plugin/
    └── 0.1.0/
        ├── plugin.toml
        └── plugin.wasm
```

## 3. Plugin Manifest (plugin.toml)

Every plugin has a TOML manifest:

```toml
[plugin]
name = "my-plugin"
version = "1.0.0"
description = "My custom DSL blocks"
author = "Your Name"
license = "MIT"

[compatibility]
min_compiler_version = "0.15.0"

[exports]
expand = "expand_block"           # Required
validate = "validate_block"       # Optional
get_keywords = "get_keywords"     # Optional (for IDE support)

[blocks]
handles = ["myblock", "another"]  # DSL blocks this plugin handles

[paths]
owns = ["src/mymodule"]           # Folders this plugin owns
auto_create = true                # Create folders on plugin import
patterns = ["*.cln"]              # File patterns in owned folders
implicit_import = true            # Files in owned folders skip import statements (plugin still declared in main.cln)
```

### Manifest Fields

| Section | Field | Required | Description |
|---------|-------|----------|-------------|
| `[plugin]` | name | Yes | Unique plugin identifier |
| | version | Yes | Semantic version (x.y.z) |
| | description | Yes | Short description |
| | author | No | Author name/email |
| | license | No | License identifier |
| `[compatibility]` | min_compiler_version | Yes | Minimum compiler version |
| `[exports]` | expand | Yes | Name of expand function |
| | validate | No | Name of validation function |
| | get_keywords | No | Name of keywords function |
| `[blocks]` | handles | Yes | List of block names |
| `[paths]` | owns | No | List of folder paths this plugin owns |
| | auto_create | No | Create folders automatically (default: true) |
| | patterns | No | File patterns recognized in owned folders |
| | implicit_import | No | Skip import statements in files inside owned folders; plugin must still be declared in main.cln (default: true) |

## 4. Plugin Source (Clean Language)

Plugins are Clean Language files that export functions.

### Required: `expand_block`

```clean
// src/main.cln

expand_block(block_name: string, attributes: string, body: string) -> string
```

| Parameter | Type | Description |
|-----------|------|-------------|
| `block_name` | string | The DSL block identifier (e.g., "server") |
| `attributes` | string | JSON object of block attributes |
| `body` | string | Raw content inside the block |
| **Returns** | string | Clean Language source code |

### Example Plugin

```clean
// my-plugin/src/main.cln

// Main entry point - called by compiler for each framework block
expand_block(block_name: string, attributes: string, body: string) -> string
    if block_name == "greet"
        return expand_greet(attributes, body)
    if block_name == "repeat"
        return expand_repeat(attributes, body)
    // Return body unchanged for unknown blocks
    return body

// Expand greet: blocks
expand_greet(attrs: string, body: string) -> string
    name = get_attr(attrs, "name", "World")
    return "print(\"Hello, " + name + "!\")\n" + body

// Expand repeat: blocks
expand_repeat(attrs: string, body: string) -> string
    count = get_attr(attrs, "count", "1")
    result = ""
    i = 0
    while i < count.toInteger()
        result = result + body + "\n"
        i = i + 1
    return result

// Helper to extract attribute from JSON
get_attr(json: string, key: string, default_val: string) -> string
    // Simple implementation - real one would parse JSON
    return default_val
```

### Optional: `validate_block`

```clean
validate_block(block_name: string, attributes: string, body: string) -> string
```

Returns empty string if valid, or error message if invalid. Called before `expand_block`.

```clean
validate_block(block_name: string, attributes: string, body: string) -> string
    if block_name == "repeat"
        count = get_attr(attributes, "count", "")
        if count == ""
            return "repeat: block requires 'count' attribute"
    return ""  // Valid
```

### Optional: `get_keywords`

```clean
get_keywords() -> string
```

Returns JSON array of keywords for IDE syntax highlighting.

```clean
get_keywords() -> string
    return "[\"greet\", \"repeat\", \"name\", \"count\"]"
```

## 5. Plugin Development Workflow

### Creating a New Plugin

```bash
# 1. Scaffold plugin project
cleen plugin create my-plugin

# Creates:
# my-plugin/
# ├── plugin.toml
# ├── src/
# │   └── main.cln
# ├── tests/
# │   └── test_expand.cln
# └── README.md
```

### Building

```bash
cd my-plugin

# Build plugin
cleen plugin build
# → Compiles src/main.cln to plugin.wasm
```

### Testing Locally

```bash
# Install to local plugins directory
cleen plugin add ./

# Create test file using plugins: block in main.cln
echo 'plugins:
    my-plugin

greet: name="Developer"
    print("Starting...")
' > test.cln

# Compile with plugins
cln compile test.cln -o test.wasm --plugins
```

```bash
# Publish to registry (future)

```

## 6. Official Frame Plugins

Plugins are loaded via the `plugins:` block in `main.cln`. This declaration is always required. There are no `import:` blocks for plugins. When `implicit_import = true` is set in a plugin's `plugin.toml`, individual source files in the plugin's owned folders do not need to declare the plugin themselves — it is already declared in `main.cln` and the compiler knows which folders it owns.

### frame.server

**Blocks:** `endpoints`

**Source:** `plugins/frame.server/src/main.cln`

**Owned Folders:** `app/server/`, `app/server/api/`, `app/server/middleware/`

```clean
// frame.server plugin - HTTP server and routing DSL

expand_block(block_name: string, attributes: string, body: string) -> string
    if block_name == "server"
        return expand_server(attributes, body)
    if block_name == "endpoints"
        return expand_endpoints(attributes, body)
    return body

expand_server(attrs: string, body: string) -> string
    port = get_attr(attrs, "port", "8080")
    host = get_attr(attrs, "host", "localhost")
    return "
start:
    _log_info(\"Server starting on " + host + ":" + port + "\")
    " + body + "
    _http_listen(\"" + host + "\", " + port + ")
"

expand_endpoints(attrs: string, body: string) -> string
    return "
functions:
    " + body + "
"
```

**Usage (via `plugins:` block in main.cln):**

```clean
// main.cln
plugins:
    frame.server

server: port=3000
    endpoints:
        GET "/hello" :
            return json({"message": "Hello World"})

        POST "/echo" :
            return json(request.body)
```

**Usage (in an owned folder — no import statement needed in the file):**

```clean
// app/server/api/users.cln
// No import needed — frame.server declared in main.cln, processes files in this folder

endpoints:
    GET "/users" :
        string result = _db_query("SELECT * FROM users", "[]")
        return json({"ok": true, "data": result})

    POST "/users" :
        return json({"ok": true})
```

### frame.data

**Blocks:** `data`

**Source:** `plugins/frame.data/src/main.cln`

**Owned Folders:** `app/data/`, `app/data/models/`, `app/data/`, `app/data/migrations/`, `app/data/`

```clean
// frame.data plugin - ORM DSL

expand_block(block_name: string, attributes: string, body: string) -> string
    if block_name == "data"
        return expand_data(attributes, body)
    return body

expand_data(attrs: string, body: string) -> string
    name = get_attr(attrs, "name", "Model")
    table = get_attr(attrs, "table", name.toLowerCase())
    return "
class " + name + "
    integer id
    " + body + "

    functions:
        save() -> boolean
            if this.id == 0
                this.id = _db_insert(\"" + table + "\", this)
                return this.id > 0
            return _db_update(\"" + table + "\", this.id, this)

        static find(id: integer) -> " + name + "
            row = _db_query_one(\"SELECT * FROM " + table + " WHERE id = ?\", [id])
            return " + name + ".fromRow(row)

        static all() -> Array<" + name + ">
            rows = _db_query(\"SELECT * FROM " + table + "\", [])
            return rows.map((row) -> " + name + ".fromRow(row))

        delete() -> boolean
            return _db_delete(\"" + table + "\", this.id)
"
```

**Usage (in an owned folder — no import statement needed in the file):**

```clean
// app/data/User.cln
// No import needed — frame.data declared in main.cln, processes files in this folder

data User
    string email
    string name
    boolean active = true
    string created_at
```

```clean
// app/data/Post.cln

data Post
    integer user_id
    string title
    string content
```

## 7. Folder Conventions

Plugins can declare **folder ownership** to provide convention-over-configuration semantics. When a plugin is declared in `main.cln` and `implicit_import = true`, files placed in that plugin's owned folders receive the plugin's context without needing an explicit import statement in each file.

### How Folder Conventions Work

```
┌─────────────────────────────────────────────────────────────────┐
│                     PROJECT INITIALIZATION                       │
│                                                                  │
│   main.cln declares:                                             │
│       plugins:                                                   │
│           frame.ui                                               │
│           frame.data                                             │
│           frame.server                                       │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                     PLUGIN LOADING                               │
│                                                                  │
│   For each plugin:                                              │
│   1. Read plugin.toml [paths] section                           │
│   2. If auto_create = true, create owned folders                │
│   3. Register folder → plugin mappings                          │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                     COMPILATION                                  │
│                                                                  │
│   For each source file:                                         │
│   1. Check if file is in a plugin-owned folder                  │
│   2. If implicit_import = true, inject plugin import            │
│   3. Apply plugin's block handlers automatically                │
└─────────────────────────────────────────────────────────────────┘
```

### Official Plugin Folder Conventions

| Plugin | Owned Folders | File Types | Purpose |
|--------|---------------|------------|---------|
| `frame.ui` | `app/web/pages/`, `app/web/components/`, `app/web/layouts/` | `.html`, `.cln` | Pages, components, layouts |
| `frame.data` | `app/data/`, `app/data/models/`, `app/data/`, `app/data/migrations/`, `app/data/` | `.cln` | Data models, ORM, queries, migrations |
| `frame.server` | `app/server/`, `app/server/api/`, `app/server/middleware/` | `.cln` | HTTP server, API routes, endpoints |
| *(core compiler)* | `app/logic/` | `.cln` | Shared business logic — always compiled, no plugin needed |
| `frame.auth` | `app/auth/` | `.cln` | Auth configuration |
| `frame.canvas` | `app/canvas/`, `app/canvas/scenes/`, `app/canvas/sprites/`, `app/canvas/audio/` | `.cln` | Canvas rendering, animation, sprites, audio |

### Implicit Import Behavior

When `implicit_import = true` in a plugin's `plugin.toml`, individual source files in the plugin's owned folders do not need to declare the plugin or add any import statement — the compiler knows the plugin owns that folder because the plugin was declared in `main.cln`. The plugin itself must always be declared in `main.cln`.

`implicit_import = true` controls whether **files skip import statements**, not whether **the plugin skips declaration**.

**Always required — plugin declaration in main.cln:**
```clean
// main.cln
plugins:
    frame.data
```

**What implicit_import = true enables — no import statement needed in individual files:**
```clean
// app/data/User.cln
// No import statement needed — frame.data is declared in main.cln and owns this folder

data User
    string email
    string name
```

### Compiler Folder Ownership Resolution

The Clean Language compiler resolves which plugin processes each source file by checking the folder ownership declared in each plugin's `plugin.toml`. This is not automatic detection — it depends entirely on which plugins are declared in `main.cln`.

**Resolution Rules:**

| File Path Pattern | Owning Plugin (when declared in main.cln) |
|-------------------|------------------------------------------|
| `app/server/`, `app/server/api/`, `app/server/middleware/` | `frame.server` |
| `app/logic/` | *(core compiler — always compiled, no plugin required)* |
| `app/data/`, `app/data/models/`, `app/data/`, `app/data/migrations/`, `app/data/` | `frame.data` |
| `app/auth/` | `frame.auth` |
| `app/canvas/`, `app/canvas/scenes/`, `app/canvas/sprites/`, `app/canvas/audio/` | `frame.canvas` |
| `app/web/pages/`, `app/web/components/`, `app/web/layouts/` | `frame.ui` |

**How It Works:**

1. The compiler reads the `plugins:` block in `main.cln` and loads each declared plugin
2. For each loaded plugin, it reads the `[paths]` section of `plugin.toml` to learn which folders that plugin owns
3. When compiling a source file, it checks which declared plugin owns the file's folder
4. If `implicit_import = true`, the plugin's blocks are available in that file without any import statement

**Example — file in an owned folder:**

```clean
// main.cln — frame.server must be declared here
plugins:
    frame.server
```

```clean
// File: app/server/api/users.cln
// No import statement needed — frame.server declared in main.cln, owns this folder

endpoints:
    GET "/users" :
        string result = _db_query("SELECT * FROM users", "[]")
        return json({"ok": true, "data": result})

    POST "/users" :
        return json({"ok": true})
```

**Important:** If `frame.server` is not declared in `main.cln`, no plugin will process this file regardless of its folder path.

### Folder Priority Rules

When multiple plugins could own the same folder:

1. **Explicit ownership wins**: First plugin to declare `owns` takes priority
2. **Nested folders are specific**: `app/data/users/` can be owned by a different plugin than `app/data/`
3. **Pattern matching**: More specific patterns match first (`*.model.cln` before `*.cln`)

### Custom Plugin Folders

Third-party plugins can declare their own folders:

```toml
# my-analytics-plugin/plugin.toml
[plugin]
name = "analytics"
version = "1.0.0"

[paths]
owns = ["src/analytics", "src/tracking"]
auto_create = true
patterns = ["*.cln"]
implicit_import = true

[blocks]
handles = ["track", "event", "metric"]
```

This creates `src/analytics/` and `src/tracking/` when the plugin is imported.

## 8. Security Model

### Compile-Time Sandbox

Plugins run in a WASM sandbox during compilation:

- **No filesystem access** (except plugin source)
- **No network access**
- **No system calls**
- **Memory isolated** per plugin
- **Deterministic** execution

### Generated Code Safety

- All generated code goes through **type checking**
- Invalid code is caught by **semantic analysis**
- Cannot bypass the **type system**

### Trust Model

| Source | Trust Level | Notes |
|--------|-------------|-------|
| Official plugins | High | Signed, verified |
| Registry plugins | Medium | Community reviewed |
| Local plugins | User-defined | Installed manually |

## 9. Testing Plugins

### Unit Tests

Test the `expand_block` function directly:

```clean
// tests/test_expand.cln

test_greet_expansion()
    result = expand_block("greet", "{\"name\": \"Test\"}", "")
    assert(result.contains("Hello, Test!"))

test_unknown_block()
    result = expand_block("unknown", "{}", "original")
    assert(result == "original")
```

### Integration Tests

Test with the compiler:

```bash
# Create test input using plugins: block
cat > test_input.cln << 'EOF'
plugins:
    my-plugin

greet: name="World"
EOF

# Compile and check output
cln compile test_input.cln -o test.wasm --plugins

# Verify WASM is valid
wasm-validate test.wasm
```

## 10. Versioning & Compatibility

### Semantic Versioning

Plugins follow **semver** (MAJOR.MINOR.PATCH):

- **MAJOR**: Breaking changes to block syntax
- **MINOR**: New blocks or features
- **PATCH**: Bug fixes

### Compiler Compatibility

Declare minimum compiler version:

```toml
[compatibility]
min_compiler_version = "0.15.0"
```

The compiler refuses to load incompatible plugins.
