### 1. ✅ Unified Manifest Format

**File**: `system-documents/MANIFEST_FORMAT_SPEC.md` (Complete specification)

Designed and documented `package.clean.toml` as the unified configuration file for Clean Language projects:

```toml
[package]
name = "my-app"
version = "0.1.0"
authors = ["Name <email>"]
edition = "2025"

[frame]
version = "0.1.0"
target = "web"
entry = "app.cln"

[frame.server]
host = "127.0.0.1"
port = 3000

[frame.build]
optimize = true
bundle = "single"

[frame.dev]
hot_reload = true
debounce_ms = 500

[build]
src = ["app", "src"]
out_dir = "dist"
```

**Key Sections**:
- `[package]` - Core metadata (name, version, authors, license)
- `[frame]` - Framework configuration (target, entry point)
- `[frame.server]` - Dev server settings
- `[frame.database]` - Database connection
- `[frame.build]` - Build options
- `[frame.dev]` - Hot reload configuration
- `[build]` - Source directories, output paths
- `[dependencies]` - External packages (future)

### 2. ✅ Manifest Parser Implementation

**File**: `frame-cli/src/manifest.rs` (580 lines)

Created comprehensive manifest parser with validation:

**Core Types**:
```rust
pub struct Manifest {
    pub package: PackageSection,
    pub frame: Option<FrameSection>,
    pub dependencies: Option<HashMap<String, DependencySpec>>,
    pub build: Option<BuildSection>,
    pub profile: Option<ProfileSection>,
}

impl Manifest {
    pub fn load(project_dir: &Path) -> Result<Self>
    pub fn validate(&self) -> Result<()>
    pub fn src_dirs(&self) -> Vec<PathBuf>
    pub fn out_dir(&self) -> PathBuf
    pub fn target(&self) -> String
}
```

**Validation Rules**:
- Package name: kebab-case, 1-64 chars, alphanumeric + hyphens
- Version: Semantic versioning (major.minor.patch)
- Target: One of `web`, `pwa`, `mobile`, `desktop`, `server`, `cli`
- Frame version: Semver format

**Backward Compatibility**:
- Supports both `package.clean.toml` (new) and `package.frame.toml` (deprecated)
- Warning displayed when using deprecated format
- Graceful fallback during transition period

### 3. ✅ Build System Integration

**Files Modified**:
- `frame-cli/src/commands/build.rs` - Uses manifest for src dirs and output paths
- `frame-cli/src/commands/serve.rs` - Uses manifest for server config

**Before (Hardcoded)**:
```rust
let cln_files = CompilerInvoker::find_cln_files(Path::new("."))?;

```

**After (Manifest-Driven)**:
```rust
let manifest = Manifest::load(Path::new("."))?;
let cln_files = manifest.src_dirs()
    .iter()
    .flat_map(|dir| CompilerInvoker::find_cln_files(dir).unwrap())
    .collect();
let out_dir = manifest.out_dir().join(manifest.target());
fs::create_dir_all(&out_dir)?;
```

**Benefits**:
- Configurable source directories
- Custom output directories
- Per-project server configuration
- Flexible build settings

### 4. ✅ Multi-File Compilation

**File**: `frame-cli/src/compiler.rs` (updated `compile_project` method)

Implemented file bundling for multi-file projects:

**Strategy**:
- Single file: Direct compilation (fast path)
- Multiple files: Concatenate into temporary bundle → compile → cleanup

**Bundling Process**:
```rust
1. Create temp directory: /tmp/frame-build/
2. Concatenate all .cln files with header comments
3. Write to bundle.cln
4. Compile bundle.cln → output.wasm
5. Clean up temporary file
```

**Bundle Format**:
```clean
// Auto-generated bundle from multiple .cln files
// Generated by Frame CLI v0.1.0
// Files: 2

// ===== File 1: ./app.cln =====
functions:
    string greet(string name)
        return "Hello, " + name + "!"

start()
    print(greet("World"))

// ===== File 2: ./lib.cln =====
functions:
    string formatMessage(string text)
        return "*** " + text + " ***"
```

**Advantages**:
- Works with current Clean compiler (single-file input)
- Preserves all function definitions
- Enables cross-file function calls
- Deterministic build order (sorted alphabetically)

**Future Enhancement**:
When Clean compiler adds native multi-file support (`--project` mode), we can switch to that for better:
- Error messages with original file:line references
- Incremental compilation
- Module-level isolation

## Technical Details

### Manifest Loading Flow

1. Check for `package.clean.toml` (preferred)
2. Fall back to `package.frame.toml` (deprecated, warn user)
3. Parse TOML → `Manifest` struct
4. Validate all fields
5. Apply defaults for missing optional fields

### Multi-File Discovery

```rust
// Scan multiple source directories
for src_dir in manifest.src_dirs() {
    if src_dir.exists() {
        let mut files = CompilerInvoker::find_cln_files(&src_dir)?;
        all_files.append(&mut files);
    }
}

// Remove duplicates and sort
all_files.sort();
all_files.dedup();
```

**Skipped Directories**: `.`, `dist`, `target`, hidden dirs

### Serve Command Updates

**Manifest-Driven Configuration**:
```rust
let manifest = Manifest::load(Path::new("."))?;

// Use manifest server config if available
let host = manifest.frame
    .and_then(|f| f.server)
    .map(|s| s.host)
    .unwrap_or_else(|| cli_host.to_string());

let port = manifest.frame
    .and_then(|f| f.server)
    .map(|s| s.port)
    .unwrap_or(cli_port);

// Serve from manifest-configured directory
let serve_dir = manifest.out_dir().join(manifest.target());
```

**Hot Reload Integration**:
- Watches files in all configured source directories
- Rebuilds using manifest target
- Serves from manifest output directory

## Known Limitations (By Design)

1. **File Concatenation**: Multi-file bundling uses concatenation
   - **Reason**: Clean compiler currently only supports single-file input
   - **Future**: Switch to native multi-file when compiler adds support
   - **Impact**: Error messages reference bundle.cln instead of original files

2. **No Dependency Resolution**: `[dependencies]` section parsed but not used
   - **Reason**: Clean package registry doesn't exist yet
   - **Future**: Phase 4+ will implement package resolution

3. **No Module System**: All functions are in global scope
   - **Reason**: Clean Language doesn't have modules yet
   - **Future**: When Clean adds modules, update bundler accordingly

4. **Single Target Per Build**: Can't build multiple targets simultaneously
   - **Reason**: Simplicity for Phase 2
   - **Future**: Add `--all-targets` flag
